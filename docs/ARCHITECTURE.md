# Architecture

The project is a local-first Vue 3/Vite application using JavaScript ES modules. The Studio UI owns source-file and native media-element lifecycles; the preferred renderer owns a WebGL2 canvas, source texture, glyph atlas, shaders, and cleanup. If WebGL2 context creation fails, bitmap preview falls back to CPU ASCII conversion and Canvas 2D drawing on the same canvas; the active backend is exposed in the UI. Shader/program errors are still surfaced rather than hidden by silently switching renderers. The video element is the sole audio clock, so playback audio remains the browser's original media audio and is not analyzed or transformed.

The default bitmap renderer uses one fragment pass: per output fragment, it samples a small neighborhood of the corresponding source cell, adjusts luminance, quantizes it to a glyph-density atlas entry, and composites the result. It intentionally avoids GPU readback during playback. Shader errors are surfaced to the UI; if WebGL2 context creation is unavailable, bitmap preview uses the Canvas 2D fallback.

Edge Detection is evaluated in the WebGL fragment shader for the live preview using luminance, optional 3×3 Gaussian smoothing, and a 3×3 Sobel gradient on cell-spaced source samples. Its magnitude uses the fixed Sobel scale (no per-frame maximum normalization) before thresholding. ASCII frame capture evaluates the same filter at 2× grid resolution on a CPU canvas so narrow contours survive downsampling; it precomputes luminance and the optional Gaussian pass once per sample before applying Sobel, avoiding repeated neighborhood work for every output pixel. PNG and HTML then draw those already-converted pages, and video capture applies it independently at each deterministic seek timestamp. `.ascii` stores the selected filter parameters as descriptive metadata as well as the resulting pages.

Flatten Colors converts samples to OKLab, applies a bilateral neighborhood filter, clusters a representative palette, and maps colors to the nearest palette entry without dithering. The CPU bilateral pass uses scalar accumulators to avoid per-neighbor array allocations during frame capture. Image palettes are built from the source image; video palettes are built once from six evenly distributed clip samples and reused for every preview/export frame. The WebGL preview uses that shared palette texture for per-cell RGB quantization; ASCII capture applies the same palette and preserves palette-only cell colors. If both filters are active, the edge gradient reads the unflattened source while edge-combined luminance uses flattened colors. Palette and filter settings are metadata in `.ascii`; the stored pages are final results.

`calculateContentLayout` is the single logical-layout function. It computes a contain-fit target no larger than 1024×576, then derives integer columns/rows by dividing that target by the measured integer font-cell width/height; final output dimensions are exact cell multiples. The source dimensions, target rectangle, grid and final dimensions are held together as the renderer's shared layout and returned by `captureText()`. The renderer recalculates it only when source dimensions, font metrics, or the cell cap change. Preview resize changes only its drawing-buffer scale. Source sampling in both WebGL and CPU capture uses the same centered contain mapping; no fit mode may crop or stretch.

Font size and line height are logical scene parameters. Canvas 2D measures the monospaced advance and the maximum used-glyph ascent/descent; cell width is the integer ceiling of the font advance, and cell height accommodates both the requested line height and glyph bounds. The same baseline and cell box are used by the atlas and vector paths. Glyph atlas rasterization uses 4× device-pixel ratio up to 8×, bounded by the GPU texture limit; this changes only atlas/drawing-buffer sharpness, never logical cell dimensions or export size. Atlas sampling accounts for the vertical flip applied during upload so glyphs remain upright. All preview canvases are displayed in contain. An alternate plain-text preview builds the same logical grid on demand; video updates in this mode use CPU canvas sampling at up to 8 fps and can be slower than GPU preview.

Rendering mode is a scene parameter with `bitmap` as the default. Vector mode parses bundled WOFF OpenType files with `opentype.js`; new Studio output uses the selectable monospaced families IBM Plex Mono and Cousine, while existing vector documents may still carry Lora paths. Browser/system font outlines are never inferred from raster pixels. It extracts quadratic/cubic outline paths in font units, retains font advance width and baseline metrics, and caches outline data by family, weight, glyph, and precision. The preview disables atlas drawing and fills cached `Path2D` geometry in a Canvas 2D context using the even-odd fill rule; this preserves counters and does not stroke glyphs. Canvas antialiases the paths. This mode is CPU-side Canvas 2D and can be slower than WebGL at large grids. Bitmap mode also uses Canvas 2D when WebGL2 is unavailable, with the same page renderer as exports.

Appearance supports custom monochrome, source RGB, and strict black-and-white modes. Black-and-white preserves the full charset's luminance-to-density mapping, fixes ink/background to white/black, and thresholds the rendered glyph mask so preview and exports contain only black and white pixels.

Vector `.ascii` documents add `render.mode: "vector"`, `render.unitsPerEm`, and one `render.glyphs` geometry map keyed by each used Unicode character. Video capture unions the required character paths across all pages. The map contains font-unit path commands and advance widths, never glyph bitmaps or the source font. Font family/weight, SIL OFL 1.1 copyright/license attribution, grid metrics, cell colors, and page text remain in the common model. PNG and the offline HTML player use the same `Path2D` fill implementation; the HTML player needs neither a system font nor a font request. Bitmap documents remain backward-compatible and omit outline data.

The **Save defaults** action stores the validated Studio scene (grid, typography, appearance, edge filter, and playback parameters) in browser `localStorage`. Startup initializes controls from those saved defaults; reset restores the saved set, or application defaults when none have been saved. Invalid or inaccessible saved data is reported in the UI rather than silently accepted.

The inspector keeps its heading and privacy footer fixed while a dedicated inner region scrolls; the application shell remains viewport-height and does not grow with the control list. Source, typography, appearance, Edge Detection, and Flatten Colors use native collapsible `details` groups. Edge display mode is a standard select with explicit options.

Exports share a versioned ASCII result model. `src/ascii-export.js` samples video on a fixed 100 ms seek timeline (not preview callbacks), optionally records its native audio track, and builds full text/color pages using the shared layout. Audio capture uses real-time playback, so it can take up to the source duration before frame conversion begins; the remaining time depends on frame count, active CPU filters, decoder seek time, and available memory. `.ascii` stores content dimensions, source/target rectangles, grid, integer cell metrics, and baseline. `src/ascii-document.js` validates and serializes that model as gzip JSON. `src/ascii-render.js` rasterizes a page to the recorded logical content dimensions for PNG (OffscreenCanvas worker where supported); `src/templates/playable-template.js` embeds the same compressed model and renderer in a standalone offline HTML player. MP4 pads odd content width/height by at most one pixel on the right/bottom; it never rescales the glyph grid.

MP4 export renders the already-converted ASCII pages to a fixed even-dimension canvas and sends each page, with its original timestamp and duration, through Mediabunny's WebCodecs H.264 encoder and MP4 muxer. For a source video, Mediabunny demuxes and decodes audio directly from the original local file; an imported `.ascii` model instead uses its embedded audio. Samples are clipped to the frame timeline, re-encoded as AAC, and muxed with the video. MP4 capture skips the real-time MediaRecorder phase used by `.ascii` export. The app checks H.264 support before frame capture and AAC support when an audio track is present; unsupported codec/device combinations fail explicitly. Chromium E2E verifies playback and both tracks. Safari still requires real-device/browser-matrix validation.

`tools/play_ascii.py` is a standard-library Python terminal player for gzip-JSON `.ascii` documents. It centers frames in the current terminal and crops overflow, selects frames by absolute document timestamps, and drops frames that arrive late rather than accumulating playback drift. An optional `--fps` caps terminal redraws; otherwise frame timestamps determine the redraw cadence. Embedded audio is decoded and played by an external FFplay process with the stored audio offset applied; system audio start/output latency means initial synchronization is approximate.

## Decisions

- No remote font/CDN dependency: the interface uses system fonts, while the reproducible ASCII renderer uses bundled local font assets.
- For reproducible outline extraction and offline playback, new Studio typography choices use bundled SIL Open Font License 1.1 monospaced fonts (IBM Plex Mono and Cousine); the Lora asset is retained for compatibility. License notices are included under `public/licenses/`. Older saved family aliases are mapped to a bundled monospace family for new source conversion.
- Node 24.20.0 is pinned in `.nvmrc`, matching the implementation environment.
- Legacy ZIP-based `.ascii` projects remain importable with fflate's 110 MiB compressed / 200 MiB expanded limits and path/entry-count checks. New `.ascii` exports are gzip-compressed UTF-8 JSON and contain no source media.
- The GPU implementation uses a single pass rather than a separate preprocess FBO to avoid frame readback and pass overhead. It samples a 3×3 neighborhood for an inexpensive area approximation.
