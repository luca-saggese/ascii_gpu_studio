# Architecture

The project is a local-first Vue 3/Vite application using JavaScript ES modules. The Studio UI owns source-file and native media-element lifecycles; the renderer owns a WebGL2 canvas, source texture, glyph atlas, shaders, and cleanup. The video element is the sole audio clock, so playback audio remains the browser's original media audio and is not analyzed or transformed.

The current renderer uses one fragment pass: per output fragment, it samples a small neighborhood of the corresponding source cell, adjusts luminance, quantizes it to a glyph-density atlas entry, and composites the result. It intentionally avoids GPU readback during playback. Shader errors are surfaced to the UI; WebGL2 absence currently reports an explicit error, with no Canvas 2D fallback yet.

Edge Detection is evaluated in the WebGL fragment shader for the live preview using luminance, optional 3×3 Gaussian smoothing, and a 3×3 Sobel gradient on cell-spaced source samples. Its magnitude uses the fixed Sobel scale (no per-frame maximum normalization) before thresholding. ASCII frame capture evaluates the same filter at 2× grid resolution on a CPU canvas so narrow contours survive downsampling; PNG and HTML then draw those already-converted pages, and video capture applies it independently at each deterministic seek timestamp. `.ascii` stores the selected filter parameters as descriptive metadata as well as the resulting pages.

Flatten Colors converts samples to OKLab, applies a bilateral neighborhood filter, clusters a representative palette, and maps colors to the nearest palette entry without dithering. Image palettes are built from the source image; video palettes are built once from six evenly distributed clip samples and reused for every preview/export frame. The WebGL preview uses that shared palette texture for per-cell RGB quantization; ASCII capture applies the same palette and preserves palette-only cell colors. If both filters are active, the edge gradient reads the unflattened source while edge-combined luminance uses flattened colors. Palette and filter settings are metadata in `.ascii`; the stored pages are final results.

Cell count is capped at 40,000. Glyph density, advance width, ascent, and descent are measured using Canvas 2D; the atlas tiles and output grid use those font metrics rather than a fixed oversized cell. The shader rounds density to one atlas glyph index and samples both local X and Y coordinates, so it draws the complete glyph instead of interpolating between adjacent glyphs or showing a single vertical slice. Atlas is rebuilt when typography changes and GL objects are disposed with the Studio. Media is held in memory through object URLs and revoked on source replacement/unmount.

The glyph atlas uses a fixed 20 px internal font size and is rasterized at 4× device-pixel ratio, up to 8×, preserving logical font metrics and subject to the GPU's maximum texture dimensions. Font size is not a user control: output detail is controlled by grid columns (32–320 in the Studio) and charset. Atlas sampling accounts for the vertical flip applied during upload so glyphs remain upright. The framebuffer uses one uniform scale based on the grid's measured aspect ratio and available preview space; it never independently stretches width and height. Atlas samples are inset by half a texel to avoid adjacent-glyph bleeding under linear filtering. The status bar reports actual framebuffer pixels separately from source dimensions and cell count. An alternate plain-text preview builds a normal monospace text grid on demand; video updates in this mode use CPU canvas sampling at up to 8 fps and can be slower than GPU preview.

The **Save defaults** action stores the validated Studio scene (grid, typography, appearance, edge filter, and playback parameters) in browser `localStorage`. Startup initializes controls from those saved defaults; reset restores the saved set, or application defaults when none have been saved. Invalid or inaccessible saved data is reported in the UI rather than silently accepted.

Exports share a versioned ASCII result model. `src/ascii-export.js` samples video on a fixed 100 ms seek timeline (not preview callbacks), optionally records its native audio track, and builds full text/color pages. `src/ascii-document.js` validates and serializes that model as gzip JSON. `src/ascii-render.js` rasterizes a page to the configured cell dimensions for PNG (OffscreenCanvas worker where supported); `src/templates/playable-template.js` embeds the same compressed model and renderer in a standalone offline HTML player.

MP4 output is surfaced in the menu for video sources but is rejected with an explicit capability error unless a deterministic encoder and MP4 muxer are available. The tested Chromium exposes real-time `MediaRecorder` MP4 but not WebCodecs; a real-time recorder cannot guarantee the deterministic frame timeline, so it is deliberately not used as an MP4 fallback.

## Decisions

- No remote font/CDN dependency: privacy and offline operation outweigh decorative font matching; the interface uses system fonts.
- Node 24.20.0 is pinned in `.nvmrc`, matching the implementation environment.
- Legacy ZIP-based `.ascii` projects remain importable with fflate's 110 MiB compressed / 200 MiB expanded limits and path/entry-count checks. New `.ascii` exports are gzip-compressed UTF-8 JSON and contain no source media.
- The GPU implementation uses a single pass rather than a separate preprocess FBO to avoid frame readback and pass overhead. It samples a 3×3 neighborhood for an inexpensive area approximation.
